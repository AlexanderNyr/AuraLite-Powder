# Полное исследование проекта AuraLite Powder

> Отчёт составлен после клонирования репозитория, загрузки всех зависимостей,
> сборки (headless + полный нативный GUI) и прохождения всех тестов.

---

## 1. Что это за проект

**AuraLite Powder** — кроссплатформенный симулятор «падающего песка»
(falling-sand) на Rust с углублённой **ядерной физикой**. Вдохновлён *The Powder Toy*,
но фокус — не просто песок/вода/огонь, а работа реактора: деление, цепная реакция,
замедление нейтронов, отравление ксеноном/иодом, термоядерный синтез, тепловые эффекты,
расплавление активной зоны.

- **Язык:** Rust (edition 2021), требует Rust ≥ 1.85
- **Лицензия:** Apache-2.0
- **Платформы:** Windows, Linux, macOS + WebAssembly (браузер)
- **Репозиторий:** github.com/AlexanderNyr/AuraLite-Powder
- **Объём кода:** ~9 660 строк Rust (40 файлов) + WGSL-шейдер + Markdown-документация
- **Версия сохранений:** `CORE_VERSION = 2`

## 3. Архитектура и поток данных

Жёсткое модульное разделение: **ядро `core` ничего не знает о рендеринге/UI/IO** и
компилируется без них. Зависимости направлены строго вниз (core ← elements ← renderer ← ui).

```
Ввод (winit / web-sys)
  → UI: AppState, BrushTool, Camera
  → SimulationState.tick():
      1. refresh_chunks()         — обновление dirty-bbox и подсчёт k-эфф
      2. process_neutron_queue()  — отложенные нейтроны: спавн/деление/поглощение
      3. physics_pass()           — гравитация, порошки, жидкости, газы (CA)
      4. hydro: equalize_surface / powder_overburden / step_devices / step_pipes
      5. reaction_pass()          — деление / синтез / распад (≥65536 ячеек — параллельно, rayon)
      6. effects_pass()           — диффузия тепла, фазовые переходы, расплавление, TNT
  → render_simulation_ex(): RGBA через color_for_element + overlay (heat/rad/density/pressure)
  → RenderBackend (softbuffer blit в pixels, либо wgpu текстура)
  → окно winit / <canvas>
```

### Ключевые типы данных

**Particle** (8 байт, `particle.rs`):
```rust
pub struct Particle { element_id: u16, temperature: u16, flags: u8, lifetime: u8 }
```
- `flags` хранит `FLAG_MOVED` (защита от двойного шага) и `FLAG_REACTED` (одна реакция на клетку).
- У радиации неиспользуемые биты флагов переиспользуются для хранения **направления полёта**
  (`heading_from_flags`/`heading_to_flags`) — треки получаются менее броуновскими.
- `temperature` — Кельвин-подобная шкала 0–5000, базовая 293 K.

**Grid** (`grid.rs`) — `Vec<Particle>` row-major, resize с миграцией частиц,
compact/full сериализация. Поля скоростей и давления хранятся отдельно от Particle
(`VelocityField { vx, vy: Vec<i8> }`, `PressureField { p: Vec<u16> }`) — это сохраняет
совместимость со старыми save-файлами.

**ChunkPool** (`utils/chunking.rs`) — чанки 32×32, `ChunkMeta` с dirty-bbox, флаг `active`,
метод `expanded_active(halo)` добавляет кольцо соседей, чтобы частицы могли падать в пустые
соседние чанки. Активные чанки пересчитываются каждый тик.

## 4. Модель физики (клеточный автомат) — `core/physics.rs`

Физика — это **клеточный автомат снизу вверх** (`step_active` идёт по строкам снизу вверх,
каждую строку перемешивая для симметрии). Маршрутизация по типу материала:

- **Порошки** (`update_powder`): накопление вертикальной скорости `vy = clamp(vy+1, ...)`,
  падение на `max_fall_speed`, при столкновении — диагональный съезд с вероятностью
  `repose_slide(id)` (угол естественного откоса; у урана 0.28, у песка 0.62).
- **Жидкости** (`update_liquid`): падение → если не падает, термоконвекция (горячая поднимается),
  затем гидростатическое растекание с `prefer_downhill` (оценка «опоры» соседних колонок).
- **Газы** (`update_gas`): плавучесть `rise_probability(id, temp)`, диффундирование вбок,
  вытеснение более тяжёлого/холодного газа над собой (`buoyancy`).
- **Радиация** (`move_radiation`): случайное блуждание (gamma 3 шага, fast-n 2, остальные 1),
  пробег ограничен `penetration_depth`, плотное экранирование (Pb/сталь > 7.0) поглощает чаще;
  gamma проходит сквозь с шансом 0.7, deposit энергии в температуру цели.
- **Статические твёрдые тела** не двигаются (стены, бетон, сталь, графит, бор, устройства).

`swap_cells` переставляет и частицы, и поля скоростей; принимающая клетка получает
`FLAG_MOVED`. Плотностное погружение `try_sink` позволяет тяжёлым порошкам
проседать сквозь жидкости (U-235 тонет в воде — есть отдельный тест).

**Тепло** (`diffuse_heat_active`): взвешенная по проводимости (`conductivity(id)`)
Якооби-итерация по 4 соседям + утечка к 293 K (для воздуха сильнее).

**Фазовые переходы** (`apply_phase_changes`): вода⇄лёд⇄пар, тяжёлая вода, пар в трубах.

## 5. Ядерная физика — `core/reactions.rs` + `simulation.rs`

Физически-правдоподобная, но упрощённая модель. Все константы — единый источник истины в
`reactions.rs`, переиспользуется элементами через re-export (вероятности не «расползаются»).

### Деление
`fission_probability(element, energy, temp)` — базовая вероятность × температурный множитель:

| Элемент | Тепловой n | Быстрый n |
|---|---|---|
| U-235 | 0.85 | 0.35 |
| Pu-239 | 0.90 | 0.40 |
| U-238 | 0.02 (порог) | 0.25 |
| Pu-240 | 0.10 | 0.30 |
| Molten Fuel | 0.50 | 0.30 |

При делении (`trigger_fission`): топливо → продукты деления (T +500 K), спавн 2–4 быстрых
нейтронов через **очередь с задержкой 1–3 тика** (≈15% — «запаздывающие» с delay 10–28,
что держит сборку критичной после мгновенного всплеска), 1–2 gamma, прогрев соседей в радиусе 2.
Также 10% шанс родить **иод-135** (далее распадается в ксенон — см. отравление), 4% — ксенон.

### Цепная реакция и критичность
- `neutron_queue: VecDeque<NeutronEvent{x,y,delay,energy}>` — отложенное распространение.
- `k_effective` пересчитывается каждый тик: `(fissile*2.5*(1+moderation))/(1+absorber*0.8+escape)`,
  масштабируется на 80. `k_extra_neutrons` добавляет лишние промпт-нейтроны при надкритичности.
- HUD: `power` (EMA делений/тик), `trend` (+/0/−), `period_ticks` (время удвоения),
  `reactor_status()` = rising/holding/dying/subcritical.

### Замедлители / поглотители / разведение
- `moderator_thermalize_chance`: тяжёлая вода 0.5 > вода 0.4 > графит 0.3 (быстрый→тепловой).
- `absorber_chance`: бор, **стержни управления** (0.92/0.70), ксенон (0.95/0.55).
- **Li-6 + n → T + He** с `LITHIUM_BREED_CHANCE=0.40`.

### Синтез
D + T при T > 1500 K (порог), вероятность 0.05/тик/пара → He + быстрый нейтрон + прогрев радиус 3
(+800 K), что лавинообразно поджигает соседние D+T.

### Распад (масштабированные периоды полураспада)
U-235→продукты деления (α), U-238→обедащённый уран, Pu-239→U-235, Pu-240→Pu-239,
T→He (β), **Xe→воздух**, **I-135→Xe-135** (иодная яма).

### Отравление (иодная яма) — реалистичная деталь
Fission рождает I-135 (half-life 2400 тиков) → Xe-135 (8000 тиков, сильный поглотитель).
Это моделирует реальную «иодную яму» реактора. Есть отдельная **миссия «Iodine pit»**:
поднять стержни и вернуть k-эфф ≥ 0.70 на 2 сек после отравления.

## 6. Гидродинамика крупного масштаба — `core/hydro.rs`

Поверх клеточного автомата — макроэффекты для больших сеток:
- `equalize_liquid_surface` — жидкость на свободной поверхности находит уровень
  (ищет «дыру» вниз у соседних колонок).
- `add_hydrostatic_pressure` — давление растёт с глубиной, статичные стены его блокируют.
- `step_pipe_network` — трубы как воздуховод: ingest в порт → hop вдоль PIPE → eject в выход
  (с учётом давления). Вода/пар переносятся сквозь стены.
- `powder_overburden_slide` — высокие колонки порошка дают редкий боковой сход (оползень),
  но не текут как жидкость.

## 7. Устройства — `core/devices.rs`

CA-логика для конструкционных/активных элементов:
- **HEATER** греет соседей, **PUMP** проталкивает жидкость (в т.ч. в трубы),
  **SENSOR** — аналоговый датчик (температура = поток излучения + k-эфф, при k>1.05 или
  потоке≥3 выдаёт spark/заряжает wire).
- **WIRE + SPARK** — простая электросеть: импульс ходит по проводам и управляет
  heater/pump/поджигает TNT.
- **FIRE** — горение с учётом кислорода (пустых клеток), тушится водой, поджигает
  горючее, ускоряется водородом; **ACID** разъедает камень/дерево/сталь → SLAG.
- **CONTROL_ROD** поглощает нейтроны и при перегреве >1600 K плавится в SLAG;
  `shift_control_rods(dy)` — ручное управление стержнями (клавиши [ ]).
- Поле давления диффундируется, высокое давление разгоняет поток и рвёт трубы/лёд.

## 8. Миссии и сценарии

**9 сценариев** (`scenarios.rs`): Empty, Bare/Controlled reactor, Critical pit (Pu-239),
Ice melt, Hourglass, Fusion cell, Coolant loop, Forest fire.

**6 миссий** (`missions.rs`) с win/fail условиями и таймерами:
1. **Hold critical** — держать k-эфф в 0.70–1.40 10 сек, не уйдя в промпт-критичность (>2.8).
2. **Iodine pit** — рестарт через отравление.
3. **Forest fire** — потушить пожар водой, сохранив лес.
4. **Keep the loop** — контур охлаждения держится 12 сек (терпимо до 4 порванных труб).
5. **Wire shot** — подать spark на провод → подрыв TNT.
6. **Filter rescue** — вода проходит сквозь фильтр, песок остаётся сверху.

Миссии сериализуются в `.aura` (`MissionSave`), есть retry/continue/abandon.

## 9. Рендеринг — `renderer/`

Абстракция `RenderBackend { init, render(&[RGBA]), resize }` + два бэкенда:
- **SoftbufferBackend** (основной, по умолчанию): `pixels` 0.15 + `softbuffer` + `winit`.
  CPU-композитор `render_simulation_ex` проецирует сетку через камеру в RGBA-фрейм,
  запекая свечение температуры и один из оверлеев (heat/radiation/density/pressure).
- **WgpuBackend** (опц.): создаёт device+очередь, компилирует `shader.wgsl`
  (fullscreen-triangle, `textureLoad` с nearest-фильтрацией + uniform-камера),
  загружает RGBA8-текстуру сетки (с 256-выравниванием строк). При отсутствии адаптера — fallback.
- Камера: зум (0.1–20) с удержанием точки под курсором, панорамирование, `world↔screen`.

Важный нюанс: egui растеризуется **процессорно** в тот же пиксель-буфер
(`ui/egui_raster.rs` — собственная программная растеризация треугольников/текстур),
чтобы панели были видны без GPU-смешивания.

## 10. UI и инструменты — `ui/`

- **AppState** — дерево: SimulationController (speed/pause/tick_rate/resize),
  PalettePanel (поиск, хотбар 1–0, избранное), ToolPanel, PropertyInspector (hover-инфо),
  SaveLoadPanel (rfd-диалоги, zstd), InfoPanel (fps/k-эфф/power/poison-бар).
- **Инструменты** (`brush.rs`): Brush (круг), Line (Брезенхем), Fill (BFS, лимит 10000),
  Eraser, Rectangle, Copy (в буфер), Stamp (из буфера с превью).
- Undo (24 шага), копирование/вставка регионов, запись GIF (R каждые 2 кадра, даунсэмплинг до 320px).
- Полноценные egui-панели: палитра с цветными превью и звёздами, слайдеры,
  кнопки сцен/миссий, обучающий туториал (5 шагов).

## 11. IO — `io/`

- **SaveFile v2** (versioned): bincode (.aura) + serde_json (.json) + опц. zstd.
  Сохраняет компактные/полные данные, очередь нейтронов, счётчики, поля скоростей/давления,
  power и состояние миссии. Есть миграция с **v1** (`SaveFileV1` → `SaveFile`),
  авто-детекция сжатия при загрузке, `apply_to(sim)` восстанавливает всё состояние.
- **GIF89a-кодер** (`gif89a.rs`) — собственная реализация: палитра 3-3-2, LZW-сжатие,
  зацикленный (NETSCAPE2.0). Используется для внутриигровой записи.

---

## 12. WebAssembly — `web/` + `wasm/`

`aura-lite-web` — shim: `WebSimulation` рендерит в `<canvas>` через `putImageData`
(`ImageData::new_with_u8_clamped_array_and_sh`). `WasmSimulation` (#[wasm_bindgen])
экспортирует tick/paint/clear/setup_demo/load_scene/shift_rods/save_bytes/load_bytes/
k_effective/power/reactor_status. Веб-сборка — однопоточная (ThreadPool — no-op),
rfd заменён на Blob. `wasm`-crate — точка входа: `start_sim()`, `create_simulation()`.

## 14. Наблюдения и оценка качества

**Сильные стороны:**
- Зрелая, продуманная архитектура с чистым разделением слоёв; ядро действительно изолировано.
- Ядерная модель не «для галочки» — реалистичные детали: запаздывающие нейтроны,
  иодная яма/ксенон, замедлители, k-эффективность с HUD, период реактора.
- Богатый геймплей: устройства (wires/sensors/pipes/heaters), давление, фазовые переходы,
  6 осмысленных миссий, 9 сцен, запись GIF, undo, copy/stamp.
- Тестирование: 52 теста покрывают гравитацию, течение воды, деление, синтез, распад,
  поглощение, трубы, фильтры, давление, сохранения, миссии — почти каждая механика.
- Тонкие оптимизации: чанки с dirty-tracking и halo, переиспользование бит флагов под
  направление радиации, параллелизм rayon для ≥65536 ячеек, плотностное погружение.

**Заметки / потенциальные улучшения (отмечены и в NUCLEAR_PHYSICS.md):**
- Параллельная ветка реакций использует rayon, но физика-проход пока последовательный.
- Температурная диффузия — простое усреднение, не уравнение теплопроводности; нет поля давления
  как полноценного решателя (давление — эвристика).
- SoA-лейаут для частиц мог бы улучшить локальность кэша (помечено как «future»).
- Нет GPU-compute для физики (только рендер wgpu), нет энергозависимости сечений нейтронов.

**Итог:** это завершённый, качественный и хорошо документированный учебно-демонстрационный
проект — полноценный «песочный» реактор-симулятор с глубокой физикой, кроссплатформенной
сборкой и solid test-покрытием. Проект собирается и проходит все тесты.
